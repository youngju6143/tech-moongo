## 1. 개요 (Core Concept)

본 프로젝트는 정적인 블로그 포스트 데이터를 **'데이터 추출 → 점수 산출 → 디자인 요소 매핑'**의 파이프라인을 통해 동적인 3D 객체(책)로 변환하는 시스템을 구축한다. 이는 텍스트 데이터를 시각적 메타포로 치환하여 사용자에게 직관적인 인사이트를 제공하는 것을 목적으로 한다.

데이터 원천은 Notion 데이터베이스이며, 각 게시글(페이지)의 본문과 메타데이터를 수집하여 4가지 정량 점수(정보량·전문성·활동성·독창성)를 산출하고, 이를 책의 두께·색상·질감·발광 등 시각 요소로 매핑한다.

## 2. 데이터 분석 및 점수 산출 로직 (Scoring Design)

모든 점수는 게시글 집합 내에서 **Min-Max 정규화**를 거쳐 0~1 범위로 환산한다.

$$\text{NormalizedScore} = \frac{x - min}{max - min}$$

### (1) 정보량 점수 (Length Score)

- **지표:** 텍스트 총 글자 수 (Length)
- **산출식:** $LengthScore = \frac{Length - min}{max - min}$ (Min-Max Normalization)
- **이론적 근거:** 정보 이론(Information Theory)에서 텍스트 길이는 정보량의 주요 프록시(Proxy)로 활용된다. 특히 Medium 등 주요 콘텐츠 플랫폼에서 활용하는 **`'읽기 시간(Reading Time) 기반 평가 모델'`**과 Shannon의 정보량 개념을 차용하여, 분량이 많을수록 콘텐츠의 풍부함(Richness)이 높다고 가정한다.

### (2) 전문성 점수 (Technical Depth Score)

- **지표:** 코드 블록(Code Block) 수 및 기술 키워드(Technical Keywords) 밀도
- **산출식:** $DepthScore = (CodeCount \times 0.4) + (KeywordCount \times 0.6)$ → Min-Max 정규화
- **이론적 근거:**
  - 소프트웨어 문서 품질 연구에 따르면 **`코드 밀도(Code Density)`**는 기술 문서의 전문성을 판별하는 핵심 지표이다.
  - 기술 키워드는 한국어 형태소 분석기(**kiwipiepy**)로 본문을 토큰화한 뒤, **TTA 정보통신용어사전** 기반 도메인 특화 어휘 사전과 매칭하여 출현 빈도를 측정한다. 이는 **TF-IDF(Term Frequency-Inverse Document Frequency)** 개념을 응용한 것으로, 도메인 어휘(React, API 등)의 밀도를 통해 콘텐츠의 기술적 깊이를 정량화한다.
  - **가중치 설정:** 초기에는 코드 블록에 높은 가중치를 부여하였으나, 설문 조사(n=49) 결과 사용자가 전문성을 인지하는 데 **기술 키워드의 영향이 유의하게 더 크다**는 점이 확인되었다(대응표본 t-검정, t(48)=-4.000, p<.0001). 이에 따라 키워드에 0.6, 코드 블록에 0.4의 가중치를 부여하도록 재조정하였다.

### (3) 활동성 점수 (Activity Score)

- **지표:** 최근 작성일(Recency), 작성 빈도(Streak)
- **산출식:** $ActivityScore = Recency + StreakBonus$ → Min-Max 정규화
  - **최근성:** 시간 감쇠 함수 $Recency = e^{-0.003 \times days}$ (작성 후 약 231일 경과 시 0.5로 감쇠)
  - **연속성:** 14일 이내 간격으로 작성된 글들을 하나의 스트릭(Streak)으로 묶어, 스트릭 길이를 보너스로 가산
- **이론적 근거:** 자기결정이론(SDT) 및 게이미피케이션(Gamification) 이론을 적용하였다. GitHub의 Contribution Graph나 Duolingo의 Streak 시스템처럼 **`지속적인 행동 유도(User Engagement)`**가 콘텐츠의 활성도를 결정짓는 핵심 요소임을 반영하였다. 최근성 가중치에는 정보 검색(IR) 분야의 **시간 감쇠 함수(Time Decay Function)** 개념을 적용하여 최신 글에 가점을 부여한다.
  _출처 : Hamari et al., "Does Gamification Work? — A Literature Review of Empirical Studies on Gamification" (2014)_

### (4) 독창성 점수 (Originality Score)

- **지표:** 본문 내 블록 타입의 다양성 (이미지·콜아웃·토글·인용·북마크 블록 수)
- **산출식:** $OriginalityScore = (0.4 \times Image) + 0.3 \times (Callout + Toggle) + 0.3 \times (Quote + Bookmark)$ → Min-Max 정규화
- **이론적 근거:** 단순 텍스트 복사·요약 글과 달리, 직접 캡처한 이미지·도식, 콜아웃/토글을 활용한 구조화, 인용/북마크를 통한 출처 연결은 작성자의 **고유한 정리·재구성 노력(Authenticity)**을 반영하는 프록시로 본다. 가중치는 설문 자유 응답에서 '직접 만든 자료(이미지/도식)'를 독창성의 핵심으로 꼽은 빈도에 근거하여 이미지 블록에 가장 높은 비중(0.4)을 부여하였다.

## 3. 종합 점수 모델 (Total Score Framework)

$$TotalScore = (Length \times 0.3) + (Depth \times 0.3) + (Activity \times 0.2) + (Originality \times 0.2)$$

- **설계 논리:** 콘텐츠 본연의 품질을 나타내는 정보량·전문성에 각 0.3의 비중을 두고, 부가적 활성 지표인 활동성과 독창성에는 각 0.2를 할당하였다. 네 점수의 가중치 합은 1.0이다. 이는 가중치 변화에 따른 결과의 안정성을 확인하는 **민감도 분석(Sensitivity Analysis)**을 통해 산출물의 신뢰도를 확보한 수치이다.

## 4. 디자인 요소 매핑 (Design Mapping)

수집된 데이터 점수를 시각 객체로 변환할 때, **Jacques Bertin의 시각 변수(Visual Variables) 이론**을 근거로 삼는다. 1967년 제안된 이 이론은 데이터 속성에 따라 적합한 시각적 표현 방식이 존재함을 명시한다.

| **시각 요소**       | **매핑 데이터**     | **매핑 논리 (Bertin의 시각 변수 이론)**                                        |
| ------------------- | ------------------- | ----------------------------------------------------------------------------- |
| **두께 (Size)**     | **정보량 점수**     | 크기(Size)는 정량적 수치 변동을 표현하는 데 가장 직관적인 변수임.             |
| **색상 (Hue)**      | **카테고리**        | 색조(Hue)는 범주형(Categorical) 데이터의 구분에 최적화된 변수임.              |
| **질감/패턴**       | **전문성 점수**     | 전문성이 높을수록 표지 패턴(plain→bordered→striped→embossed) 복잡도를 높여 차별화함. |
| **발광 (Value)**    | **활동성 점수**     | 최근·연속 작성 글일수록 책 고유색으로 은은하게 빛나게 하여(emissive) 사용자 주의를 유도하고 최신성을 강조함. |

> 책의 높이(Height)는 제목 길이에 비례하여 시각적 다양성을 부여하는 보조 요소로, 점수 산출 지표에는 포함하지 않는다.

또한 책의 **배치**는 카테고리별로 군집(클러스터링)한 뒤, 각 군집 내부에서 작성일 오름차순으로 정렬하여 책장(Shelf)과 서가(Bookcase)에 채워 넣는다. 이로써 색상 군집을 통해 학습 편향을, 군집 내 흐름을 통해 시간순 성장을 동시에 읽을 수 있게 한다.

## 5. 결론 및 기대 효과

본 설계는 블로그의 파편화된 데이터를 **객관적 지표로 정량화**하고, 이를 학술적 근거에 기반한 **시각적 은유(Visual Metaphor)**로 변환한다. 이를 통해 사용자는 자신의 학습 이력과 콘텐츠의 질적 수준을 한눈에 파악할 수 있는 직관적인 3D 서재 경험을 제공받게 된다.

## 6. 시스템 아키텍처

본 시스템은 프론트엔드와 백엔드를 분리한 모노레포(monorepo) 구조로 구성된다.

- **Frontend (`apps/web`):** React + TypeScript + Vite 기반. Three.js로 3D 서재를 렌더링하고, TanStack Query로 서버 상태를, Zustand로 전역 UI 상태를 관리한다.
- **Backend (`apps/api`):** FastAPI(Python) 기반. Notion API 프록시(토큰을 서버에만 보관), kiwipiepy 기반 한국어 키워드 추출, scikit-learn 기반 TF-IDF 벡터화 및 코사인 유사도 분석을 담당한다.

**데이터 흐름:** `Notion DB → (백엔드 프록시) 본문·메타데이터 수집 → 점수 산출(정보량·전문성·활동성·독창성) → TF-IDF 유사도 분석 → 3D 디자인 요소 매핑 → Three.js 렌더링`
